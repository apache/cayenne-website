This repository contains the sources for the Apache Cayenne website:

* https://cayenne.apache.org/
* [Apache GitHub repository](https://github.com/apache/cayenne-website)

The site has two parts:

* The marketing site, generated by Hugo from `site/`.
* Versioned documentation, generated by Antora from AsciiDoc sources in the main Cayenne repository.

## Requirements

* [Maven](https://maven.apache.org/) 3.9 or newer. Maven is the recommended entry point for building and developing the site.
* Git, with access to the Cayenne repository and the documentation branches configured in `docs/antora-playbook.yml`.

Maven provisions the Node-based toolchain for the project. It downloads the configured Node.js and Corepack versions into the local `node/` directory, runs the immutable Yarn installation, and installs the pinned development dependencies, including Hugo Extended, Antora, and the front-end packages.

A system Node.js, Corepack, Yarn, or Hugo installation is not required when using Maven.

## Development with Maven

Clone the website repository and start the development server:

```bash
git clone https://github.com/apache/cayenne-website.git
cd cayenne-website
mvn -Pdev-server
```

The `dev-server` profile:

1. Installs Node.js and Corepack into `node/` when necessary.
2. Runs `yarn install --immutable` through Corepack.
3. Builds the Antora documentation.
4. Starts the Hugo development server with live reload.

The server uses port `8080` by default:

```text
http://localhost:8080/
```

To use another port:

```bash
mvn -Pdev-server -Ddev.port=3000
```

The selected port must be available before starting the server. Stop the server with `Ctrl+C` when finished.

## Full production build

Build the complete static site with Maven:

```bash
mvn clean package
```

The generated output is written to:

```text
target/site/
```

The marketing site is placed directly under `target/site/`, and the Antora documentation is placed under `target/site/docs/`.

To preview the generated files with a static server:

```bash
npx --yes serve target/site
# or: python -m http.server -d target/site 8080
```

## Link validation

Run Maven’s verification phase to build the complete site and check links in the generated output with Linkinator:

```bash
mvn clean verify
```

The check scans `target/site/` after Hugo and Antora finish. Its settings are stored in `test/linkinator.config.json`; external URLs and known local-development examples are skipped, while local pages, assets, clean URLs, and fragments are checked. Results are written to `target/linkinator-report.csv`.

## Publishing

The Maven `publish` profile builds the production site and publishes `target/site/` to the configured SCM branch using Maven SCM Publish Plugin:

```bash
mvn -Ppublish -Dmsg="Describe the site change"
```

Review `pubScmUrl`, `scmBranch`, and `hugo.baseurl` in `pom.xml` before publishing. Publishing changes the remote website branch, so run it only when you intend to update the published site.

## Optional direct Yarn commands

Direct Yarn commands are available for frontend-focused work, but Maven is preferred for normal development because it provisions the complete toolchain and runs the same build steps used by the Maven profiles.

Enable Corepack and install dependencies manually only when needed:

```bash
corepack enable
yarn install --immutable
```

Useful direct commands are:

```bash
yarn run build       # build Hugo and Antora output
yarn run site        # build the Hugo site only
yarn run docs        # build Antora documentation only
yarn run site:watch  # run the Hugo development server
```

## Website content

### News

Add a Markdown file under `site/content/news/` with TOML front matter:

```markdown
+++
title = "Cayenne X.X Released"
date = 2026-01-01
+++

Content goes here.
```

News pages are rendered under `/:year/:month/:contentbasename/` and listed on the news page.

### Release information

When adding or updating a Cayenne release:

1. Update `site/data/cayenne.toml` and related download data when needed.
2. Add or update the release news article.
3. Add the matching documentation branch and version settings to `docs/antora-playbook.yml` when documentation should be published.
4. Update `site/static/.htaccess` redirects if legacy URLs are affected.
5. Run `mvn clean package` and inspect the generated site.

### Contributors

Edit `site/data/contributors.toml`, then run `mvn clean package` or use the Maven development server to verify the result.

## Documentation

The AsciiDoc source is maintained in the main Cayenne repository, not in this website repository. The Antora playbook selects the Cayenne branches and `docs/*` start paths to publish.

The supplemental Antora UI files are maintained in `docs/supplemental-ui/`. They contain the Cayenne-specific header, footer, styles, and helper code layered on top of the Antora Default UI.

Javadoc is not generated or hosted by this website. The documentation contains a Javadoc article that links to the external `javadoc.io` service.

## Source layout

```text
cayenne-website/
├── package.json              # Yarn scripts and dependencies
├── yarn.lock                 # Yarn 4 lockfile
├── .yarnrc.yml               # Yarn configuration
├── pom.xml                   # Maven build, development, and publish profiles
├── docs/
│   ├── antora-playbook.yml   # Antora content sources, UI bundle, and output
│   ├── cayenne/legacy/       # Four standalone legacy Antora components
│   │   ├── 1.2/              # Component metadata, page, nav, attachment
│   │   ├── 2.0/
│   │   ├── 3.0/
│   │   └── 3.1/
│   └── supplemental-ui/      # Cayenne-specific Antora UI files
├── test/
│   └── linkinator.config.json # Generated-site link-check configuration
└── site/
    ├── hugo.toml             # Hugo configuration and mounts
    ├── content/              # Marketing Markdown pages and news
    ├── data/                 # TOML site data
    ├── assets/sass/          # Hugo Pipes Sass sources
    ├── layouts/              # Hugo templates
    └── static/               # Copied assets and Apache redirects
```

Maven-managed and generated files are not committed. This includes `node/`, `target/`, `node_modules/`, `.yarn/`, and `site/resources/_gen/`.
