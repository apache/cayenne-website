Object Query Language

An ObjectSelect or a ColumnSelect can be created from a String. This is an alternative to the fluent API. E.g.:

List<Artist> artists = ObjectSelect
        .parse(Artist.class, "from Artist where name like $name order by dateOfBirth desc limit 10", "A%")
        .select(context);

The parser produces the same query object that the fluent API would, so everything said about ObjectSelect above applies. The parsed query can be customized further with the fluent API before it is executed:

List<Artist> artists = ObjectSelect
        .parse(Artist.class, "from Artist where name like $name", "A%")
        .localCache("artists")
        .pageSize(50)
        .select(context);

Query Structure

[ select [ distinct ] columns ]
from Entity
[ where     expression ]
[ having    expression ]
[ order by  orderings ]
[ limit n [ offset m ] ]
[ prefetch  paths ]

The clauses must follow in this order, and all of them, except for from, are optional (even select!). Here are the rules of the language:

  • There is a single root entity, named in the from clause. All other entities are reached via the relationship paths starting at the root (paintings.gallery.name), so there are no entity aliases and no explicit joins. Just like in expressions, a join is made outer by appending ` to a path component (`paintings), and a join is split from the other joins over the same path with an alias (paintings#p1).

  • Every expression above, as well as every column and ordering, follows the syntax of Cayenne expressions, the same one that ExpressionFactory.exp(..) takes. Anything that is valid in an expression is valid in a query: comparisons, like, in, between, arithmetics, functions, db: paths, etc.

  • The keywords are case-sensitive, and must be spelled exactly as shown here, which is also true for the expressions. The words that start the clauses are not reserved, and can be used as property names. The only reserved word is self, that denotes the root object. A property called "self" has to be written as obj:self.

  • A query with no select clause, or the one with select self, fetches the root objects and is an ObjectSelect. Any other select clause results in a ColumnSelect.

  • There is no group by clause. Just like with the fluent ColumnSelect, when any of the columns is an aggregate function, all the other columns become the grouping columns.

  • Only selecting queries are supported. There is no update or delete.

Parameters

A parameter is a name prefixed with $, the same as in expressions. The values are passed to the parse(..) method and are bound in the order in which the parameters first appear in the String. If the same name is used more than once, it takes a single value that is bound in all those places. A value can be anything that is a valid expression operand: a scalar, a collection for in, a persistent object to match a relationship, etc.:

List<Painting> paintings = ObjectSelect
        .parse(Painting.class,
                "from Painting where artist = $artist and estimatedPrice between $low and $high",
                artist, 10, 500)
        .select(context);

The parameters can be used anywhere in the expressions, including the nested selects. limit and offset only take integer literals.

Java API

There are four methods to parse a query, that differ in the type of the result:

// any query. Returns either an ObjectSelect or a ColumnSelect
FluentSelect<?, ?> q1 = ObjectSelect.parse("from Artist");

// a query of the root objects. "DataRow.class" is used to fetch the data rows instead of objects
ObjectSelect<Artist> q2 = ObjectSelect.parse(Artist.class, "from Artist");
ObjectSelect<DataRow> q3 = ObjectSelect.parse(DataRow.class, "from Artist");

// a query with a single column
ColumnSelect<String> q4 = ObjectSelect.parseColumn(String.class, "select name from Artist");

// a query with multiple columns
ColumnSelect<Object[]> q5 = ObjectSelect.parseColumns("select name, dateOfBirth from Artist");

The last three are there to avoid the type casts. They throw an exception if the query is of a different kind, e.g. if a select clause is passed to parse(Artist.class, ..).

The parser needs no mapping information, so the names of entities and properties, as well as the types of the columns, are only checked when the query is executed.

Examples

Each example shows a query String and the same query built with the fluent API.

Objects with a filter, ordering and a limit
from Artist where name like 'A%' order by dateOfBirth desc, name asc insensitive limit 10 offset 20
ObjectSelect<Artist> query = ObjectSelect.query(Artist.class)
        .where(Artist.NAME.like("A%"))
        .orderBy(Artist.DATE_OF_BIRTH.desc(), Artist.NAME.ascInsensitive())
        .limit(10)
        .offset(20);

An ordering is an expression, optionally followed by asc (the default) or desc, and then optionally by insensitive.

Joins

The joins are implied by the paths. Here is an outer join, matching the artists with no paintings:

from Artist where paintings+ = null
ObjectSelect<Artist> query = ObjectSelect.query(Artist.class).where(Artist.PAINTINGS.outer().isNull());

And here are two separate joins over the same relationship, matching the artists that have both paintings:

from Artist where paintings#p1.title = 'P1' and paintings#p2.title = 'P2'
ObjectSelect<Artist> query = ObjectSelect.query(Artist.class)
        .where(Artist.PAINTINGS.alias("p1").dot(Painting.TITLE).eq("P1"))
        .and(Artist.PAINTINGS.alias("p2").dot(Painting.TITLE).eq("P2"));
Columns
select name, dateOfBirth from Artist order by name
ColumnSelect<Object[]> query = ObjectSelect
        .columnQuery(Artist.class, Artist.NAME, Artist.DATE_OF_BIRTH)
        .orderBy(Artist.NAME.asc());

The result is a List<Object[]>. With a single column it is a list of values:

select distinct gallery.name from Painting
ColumnSelect<String> query = ObjectSelect
        .columnQuery(Painting.class, Painting.GALLERY.dot(Gallery.NAME))
        .distinct();

A column can be any expression, and it can have an alias (the same as BaseProperty.alias(..)):

select upper(name) as upperName, length(trim(name)) as nameLength from Artist
Aggregates
select artist.name, sum(estimatedPrice), count(*)
from Painting
having sum(estimatedPrice) > $min
order by artist.name
ColumnSelect<Object[]> query = ObjectSelect
        .columnQuery(Painting.class,
                Painting.ARTIST.dot(Artist.NAME),
                Painting.ESTIMATED_PRICE.sum(),
                PropertyFactory.COUNT)
        .having(Painting.ESTIMATED_PRICE.sum().gt(min))
        .orderBy(Painting.ARTIST.dot(Artist.NAME).asc());

artist.name becomes a grouping column here, as the other columns are aggregates.

Objects as columns

self is the root object, and a relationship path is a related object. Here each row is an Object[] with an Artist and a Long:

select self, count(paintings+) from Artist order by count(paintings+) desc
ColumnSelect<Object[]> query = ObjectSelect
        .columnQuery(Artist.class, Artist.SELF, Artist.PAINTINGS.outer().count())
        .orderBy(Artist.PAINTINGS.outer().count().desc());

A to-one relationship gives a related object in each row:

select title, artist, gallery from Painting
ColumnSelect<Object[]> query = ObjectSelect
        .columnQuery(Painting.class, Painting.TITLE, Painting.ARTIST, Painting.GALLERY);

With a to-many relationship a row is repeated for each related object. This is the same as flat() in the fluent API:

select name, paintings from Artist
ColumnSelect<Object[]> query = ObjectSelect
        .columnQuery(Artist.class, Artist.NAME, Artist.PAINTINGS.flat());

In both cases a row with no related object is still present in the result, with a null in place of the object. To exclude such rows, add a condition to the where clause, e.g. where exists paintings.

Subqueries

A nested select in parentheses can be used with exists, not exists, in, not in, all and any. It has the same structure as the main query, except for prefetch. Its paths are relative to its own root, and enclosing(..) is used to refer to the main query:

from Artist where exists (
    from Painting where artist = enclosing(self) and estimatedPrice > $price)
ObjectSelect<Artist> query = ObjectSelect.query(Artist.class)
        .where(ExpressionFactory.exists(ObjectSelect.query(Painting.class)
                .where(Painting.ARTIST.eq(Artist.SELF.enclosing()))
                .and(Painting.ESTIMATED_PRICE.gt(price))));

enclosing(self) is the root object of the enclosing query, enclosing(name) is its property, and enclosing(enclosing(self)) goes two levels up.

in, all and any take a nested select with a single column:

from Painting where artist.name in (select name from Artist where dateOfBirth < $date)

from Painting where estimatedPrice > all (select estimatedPrice from Painting where title = 'P2')

from Painting where estimatedPrice = any (select max(estimatedPrice) from Painting)
ObjectSelect<Painting> query = ObjectSelect.query(Painting.class)
        .where(Painting.ARTIST.dot(Artist.NAME).in(
                ObjectSelect.columnQuery(Artist.class, Artist.NAME)
                        .where(Artist.DATE_OF_BIRTH.lt(date))));
When there is no need for a nested select with its own conditions,exists over a path is shorter: from Artist where not exists paintings.
DbEntity as a root

A root prefixed with db: is a name of a DbEntity. Such a query fetches the data rows, and all its paths are the DB paths, with no need for a db: prefix:

from db:ARTIST where NAME like 'A%' order by ID desc
ObjectSelect<DataRow> query = ObjectSelect.dbQuery("ARTIST")
        .where(ExpressionFactory.likeDbExp("NAME", "A%"))
        .orderBy(new Ordering(ExpressionFactory.dbPathExp("ID"), SortOrder.DESCENDING));
Prefetching

prefetch is a comma-separated list of relationship paths, each optionally followed by the prefetch semantics - joint, disjoint or disjointById. If omitted, Cayenne picks the default semantics, the same as with prefetch(String, int):

from Artist where name = $name prefetch paintings joint, paintings.gallery
ObjectSelect<Artist> query = ObjectSelect.query(Artist.class)
        .where(Artist.NAME.eq(name))
        .prefetch(Artist.PAINTINGS.joint())
        .prefetch("paintings.gallery", PrefetchTreeNode.UNDEFINED_SEMANTICS);
